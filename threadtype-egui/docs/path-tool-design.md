## 1. 目指す体験

文字の「芯」をパスとして描き、その途中の好きな位置に幅コントローラーを置く。
コントローラーを動かすと、前後へ滑らかにつながる太さを付けられる。
始点と終点では、直線の切り口の角度を15度刻みで調整する。
芯・太さ・切り口を後から編集でき、仕上がりをSVGの塗り輪郭として書き出す。

ユーザー回答で確定した方針：

- 最初の完成形は、文字やロゴを作ってSVGで書き出すパス編集ツール。TTF出力は初期版の対象外。
- 太さは左右対称を基本に、左右の太さを個別にも調整できる。
- 15度刻みで変えるのは、始点・終点の平らな切り口の角度。

角度を画面基準とするか接線基準とするかなど、詳細な操作仕様は引き続き設計する。

## 3. 要件案と未決事項

ユーザー発言から読み取れる必須要件：

- SVGパスに相当する芯を描いて編集できる。
- パス上の任意位置に幅コントローラーを追加し、太さを変えられる。
- コントローラー間の太さは滑らかにつながる。
- 太さは左右対称を基本に、左右個別にも調整できる（ユーザー確認済み）。
- 始点と終点の平らな切り口を、個別に15度刻みで調整できる（切り口の角度であることをユーザー確認済み）。
- それらを組み合わせて文字やロゴを制作し、SVGで書き出せる（初期版の目的としてユーザー確認済み）。

MVPの提案：

- 直線と三次ベジェのペン入力、アンカー・接線ハンドル編集、開いたパスを優先。
- 幅コントローラーの追加／削除／パスに沿った移動／幅の数値入力。
- 左右対称を初期状態とし、必要なら左右個別の幅に切り替える。
- 端点にも幅を保持。切り口の角度は開始・終了で独立。
- 複数ストローク、レイヤー、選択・移動、Undo/Redo、再編集可能な保存、SVG出力。
- 芯と操作ハンドルを隠す仕上がり表示。

後続候補：閉じた芯、SVGの読み込み、TTF、筆圧入力、文字組み、可変フォント。
閉じた芯を扱う時は切り口を無効とし、継ぎ目の幅と傾きを周期的につなぐ。

まだ確定しない事項：

1. 切り口の角度基準：画面に対する角度か、接線に対する角度か。
2. 入力はペン操作が中心か、フリーハンドも必要か。外部SVG読込の優先度。
3. Windowsを最初の対象とするか、macOSも同時に対象にするか。
4. 既存ThreadShapeファイルやペグ編集の互換性を新ツールにも必要とするか。

## 4. 実装の分け方

第一候補はRust/eguiを維持し、既存アプリの基盤に独立した新パスモデルを接続する構成。
別製品としての名前・拡張子・配布構成は要件確定後に決める。
既存のペグソルバーを新パスの土台にせず、再利用するUIを新モデルに適応させる。

提案する新モジュール（まだ存在しない）：

| モジュール | 責務 |
| --- | --- |
| `path_model.rs` | 安定ID付きのパス・アンカー・幅・端点・保存形式 |
| `path_edit.rs` | ペン入力、選択、ドラッグ、分割・削除、操作単位の履歴 |
| `width_profile.rs` | 弧長と位置の対応、左右の幅補間 |
| `stroke_outline.rs` | 可変幅輪郭、端点、角、自己交差の処理 |
| `path_render.rs` | 輪郭からの表示、ヒット判定、ハンドル、キャッシュ |
| `path_export.rs` | 共通輪郭をSVGへ書き出す処理 |

依存の流れ：編集 → 芯＋幅＋端点 → 共通輪郭生成 → 画面／SVG／将来のTTF。
画面とSVGで別々に幅を計算しない。座標変換は表示境界へ寄せ、幾何はドキュメント座標で扱う。

保存する編集データの概念形：

```text
PathDocument { version, strokes, layers }
Stroke { id, centerline, width_keys, start_cap, end_cap, join_style }
Centerline { nodes: [Node], segments: [Segment], closed }
Node { id, position, handle_in, handle_out, mode: corner | smooth }
Segment { id, from_node, to_node, kind: line | cubic }
WidthKey { id, attachment: (segment_id, t), left, right, linked }
Cap { kind: flat, angle, reference: world | tangent_relative }
```

`left/right` は芯からの距離で、合計が全幅。常に非負の有限値とする。
添字を永続参照に使わず、パス・区間・コントローラーに安定IDを持たせる。
最初は幅0の端点による尖りを扱い、内部の幅0は輪郭が分離するケースとして検証する。

## 5. 太さの位置と滑らかさ

幅コントローラーの表示位置は、芯のアンカーとは別に曲線上へ自由に置ける。
クリック位置から最近点を求め、対応する区間IDとパラメーターtを保存する。
芯の形を変えた時は同じ区間のtに付いて動く仕様を第一案とする。

一方、幅を補間する軸には曲線上の距離（弧長）を使う。
tの間隔は見た目の距離と一致しないため、保存上の位置と補間軸を分ける。
区間分割時は分割位置に応じてtを新しい区間へ写し替え、幅とコントローラー位置を保つ。
削除時の再配置・パス反転時の左右交換と端点交換も、操作仕様として定義する。

第一候補は幅が過剰に膨らみにくい、形状を保つ区分的三次補間。
単に補間後に負値を0へ切り詰める方式は折れを生み得るため、補間自体で非負性を扱う。
通常の滑らかな区間では幅の一階微分を連続とし、芯の角ではジョインを明示する。
重複位置のコントローラーは統合または移動制限し、ゼロ長の補間区間を作らない。

## 6. 輪郭と切り口

芯C(s)の進行方向から単位法線N(s)を作り、基本の側面を次で定義する：

```text
L(s) = C(s) + N(s) * left(s)
R(s) = C(s) - N(s) * right(s)
```

これは設計上の出発点。急カーブで幅が大きい場合は折り返しや自己交差が発生し得る。
曲率、幅の変化、近似誤差に応じて分割し、局所輪郭の重なりを整理する処理が必要。
ゼロ長区間、接線が0の点、尖点、180度の折り返しは専用に扱う。
既存の結合関数が新しい輪郭にも十分かは、試作で確認してから採用する。

切り口の第一案は「芯の端点を通る直線」を回して側面との交点を端にする方式。
0度の表示は画面の水平線、15度スナップはドキュメント座標で計算する案。
接線相対モードは、接線に直交する切断を0度として別に定義できる。

切り口を傾けると側面の延長が必要な場合があるため、端の局所形状を延長して交点を求める。
パス全体を半平面で切ると、戻ってくる別の部分まで切れるため、端点付近だけへ適用する。
切り口が芯の接線と平行な場合や、極端に長い端を生む場合は有限の通常キャップを作れない。
その角度は適用不可としてハンドルと理由を表示し、直前の有効形状を保つ案とする。
無言の角度補正は行わない。長さ上限と境界付近の操作感は試作で決める。

## 7. 表示・保存・SVGの品質

芯・幅・端点を編集の正本として保存し、生成した輪郭はキャッシュにする。
普通のSVG出力は生成した塗り輪郭。SVGだけから幅コントローラーを復元できるとはしない。
専用プロジェクト保存が再編集を保証する。輪郭を確定する操作を追加する場合も元データを残す案。

試作では精度を制御したポリライン出力を許容するが、これは曲線のままの出力とは区別する。
文字制作の製品版で三次ベジェの輪郭出力を必須にするかは確認し、必要なら誤差を制限した
曲線フィットと、その後の自己交差・穴・切り口保持の再検証を追加する。

表示精度はズームに応じて変えてよいが、確定出力の精度はズームから独立させる。
変更したストロークのみ再計算し、ドラッグ中に全レイヤーの高精度結合を毎回行わない。
近似許容誤差と許容する表示／出力差は試作で数値化する。

## 8. 最初の検証と実装順

1. **既存アプリの基準確認**：対象OSで既存テストと起動、保存、SVG出力を確認する。
2. **幾何の小さな試作**：直線・S字・強いカーブに幅点を置き、左右幅と斜めの切り口を検証。
3. **操作の試作**：ペン、幅ハンドル、端点回転、Undoを同じキャンバスで操作できるようにする。
4. **MVP統合**：複数パス、保存・再読込、SVG、レイヤーと仕上がり表示。
5. **拡張**：優先度に従ってSVG読込、曲線出力の改善、フォント制作を接続する。

受入シナリオ案：

- S字の3か所に幅点を置き、点を移動しても意図しない膨らみや幅の段差が出ない。
- 幅点を左右個別に動かしても、芯の位置は変わらない。
- パス区間を分割しても、形と幅点の位置が変わらない。
- 開始と終了の切り口を別々に15度ずつ回せる。平行になる角度では形状を破壊しない。
- 1回のドラッグを1回のUndoで取り消せ、Escでドラッグ開始時へ戻せる。
- 交差する画と穴を含む「A」「O」相当の形を作り、出力で穴が潰れない。
- 保存・再読込後に芯、幅、切り口を再編集できる。
- 同じ形を異なるズームからSVG出力しても同じ輪郭になる。
